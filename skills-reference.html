to-prd

Invoke: @to-prd  ·  Output: PRD-*.md

  • Synthesizes — no user interview
  • Uses repo vocabulary & ADRs
  • Identifies deep modules
  • Records impl. & testing decisions
  • Explicit out-of-scope section

to-tasks

Invoke: @to-tasks  ·  Output: tasks-*.md

  • Vertical tracer-bullet slices
  • All layers end-to-end per slice
  • Tagged AFK or HITL
  • Ordered by Blocked by deps
  • Each slice independently demoable

TypeScript: PRD Deep Module Contract

to-prd identifies deep modules — large encapsulated behavior behind a small, stable interface. 

// Deep module: narrow interface, rich implementation hidden inside
interface WorkoutTemplateCatalog {
  list(): WorkoutTemplate[];
  createFromWorkout(workout: Workout, name: string): WorkoutTemplate;
  rename(id: string, newName: string): void;
  delete(id: string): void;
}

// Testing decision from the PRD: test at service boundary, not internals
describe('WorkoutTemplateCatalog', () => {
  it('persists a template and restores it after reload', () => {
    const db = new LocalStorageAdapter();
    const catalog = new WorkoutTemplateCatalogService(db);
    catalog.createFromWorkout(completedWorkout, 'Push Day A');

    // Simulate reload — new instance, same storage
    const restored = new WorkoutTemplateCatalogService(db);
    expect(restored.list()).toHaveLength(1);
    expect(restored.list()[0].name).toBe('Push Day A');
  });

  it('rejects blank template names', () => {
    const catalog = new WorkoutTemplateCatalogService(new LocalStorageAdapter());
    expect(() => catalog.createFromWorkout(completedWorkout, '   '))
      .toThrow('Template name must not be blank');
  });
});

Problem & Solution

User-facing problem statement and high-level answer.

Modules, interfaces, schemas, and what/how to test — no file paths.

AFK vs Needs Human Input

AFK — Away From Keyboard

Issue is clear. Agent classifies, plans (if complex), and implements autonomously.

  • Title + description are specific and unambiguous
  • Scope is well-defined, no critical unknowns
  • Human can also force AFK by pre-adding the afk label

Needs Human Input

Issue is ambiguous. Agent posts all blocking questions as one comment and waits.

  • Requirements missing key details
  • Multiple valid interpretations with different outcomes
  • Agent re-evaluates after each reply and can follow up

TypeScript: Issue classification shape 

type IssueVerdict = 'afk' | 'needs-human-input';
type IssueComplexity = 'simple-task' | 'complex-task';

interface IssueClassification {
  verdict: IssueVerdict;
  /** Only present when verdict is 'afk' */
  complexity?: IssueComplexity;
  /** Blocking questions; only present when verdict is 'needs-human-input' */
  questions?: string[];
}

// The model produces this decision from title + description alone.
// If the human pre-adds the 'afk' label, the ambiguity step is skipped entirely.
const example: IssueClassification = {
  verdict: 'afk',
  complexity: 'complex-task',
  // → workflow runs: to-prd → to-tasks → implement → draft PR
};

const ambiguousExample: IssueClassification = {
  verdict: 'needs-human-input',
  questions: [
    '1. Should the template be editable after creation, or read-only?',
    '2. Which storage backend: localStorage only, or also cloud sync?',
  ],
  // → workflow posts questions as one issue comment and stops.
};
function buildAgentPrompt({ taskSliceId, tasksFile, prdFile }: AgentPromptInput): string { const tasks = readFileSync(tasksFile, 'utf8'); const prd = readFileSync(prdFile, 'utf8'); // Extract only the relevant slice to keep the prompt focused const sliceMatch = tasks.match( new RegExp(`(## ${taskSliceId}[\\s\\S]*?)(?=\\n## |$)`) ); if (!sliceMatch) throw new Error(`Slice ${taskSliceId} not found in ${tasksFile}`); return [ '## Task', sliceMatch[1].trim(), '', '## Product context (PRD)', prd.trim(), '', '## Instructions', '- Implement the slice end-to-end (all layers).', '- Write tests that verify acceptance criteria.', '- Do not modify the PRD or tasks file.', ].join('\n'); } // Usage const prompt = buildAgentPrompt({ taskSliceId: 'WT-1', tasksFile: 'tasks-workout-templates.md', prdFile: 'PRD-workout-templates.md', }); console.log(prompt);

Tips for writing effective issues

  • State the desired behaviour, not the implementation
  • Include acceptance criteria in the description if you have them
  • Add the afk label to bypass ambiguity check
  • Answer clarifying questions in one reply to resume faster
  • Complex issues get a PRD + tasks file committed to the branch
  • Check the draft PR description for the model’s plan
