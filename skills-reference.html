issue-automate

Open an issue. The agent enforces trigger guards first, then checks ambiguity (unless afk is already set), branches from main, and either implements directly or plans through PRD/tasks only when needed.
Ambiguous issues pause for one grouped reply before continuing.

TypeScript: Issue classification shape 

type IssueVerdict = 'afk' | 'needs-human-input';
  type IssueComplexity = 'simple-task' | 'complex-task';

  interface IssueClassification {
    verdict: IssueVerdict;
    /** Only present when verdict is 'afk' */
    complexity?: IssueComplexity;
    /** Blocking questions; only present when verdict is 'needs-human-input' */
    questions?: string[];
  }

  // The model decides from title + description, then the workflow acts on the result.
  // If the human pre-adds the 'afk' label, the ambiguity step is skipped entirely.
  const simpleExample: IssueClassification = {
    verdict: 'afk',
    complexity: 'simple-task',
    // → workflow labels simple-task, creates AFK/issue-N from main, runs implement + review, then opens a draft PR
  };

  const complexExample: IssueClassification = {
    verdict: 'afk',
    complexity: 'complex-task',
    // → workflow labels complex-task, creates AFK/issue-N from main, writes PRD/tasks only if needed, then opens a draft PR
  };

  const ambiguousExample: IssueClassification = {
    verdict: 'needs-human-input',
    questions: [
      '1. Should the template be editable after creation, or read-only?',
      '2. Which storage backend should be supported first?',
    ],
    // → workflow posts one comment with all blockers, labels needs-human-input, then waits for a reply.
  };

TypeScript: Workflow decision sketch 

type WorkflowTrigger = 'issues.opened' | 'issue_comment';
  type WorkflowPath = 'noop' | 'clarify' | 'branch' | 'simple-task' | 'complex-task' | 'draft-pr';

  interface WorkflowDecision {
    trigger: WorkflowTrigger;
    labels: string[];
    path: WorkflowPath;
  }

  const ignoredCommentDecision: WorkflowDecision = {
    trigger: 'issue_comment',
    labels: [],
    path: 'noop',
    // → issue_comment does nothing unless needs-human-input is present
  };

  const resumeDecision: WorkflowDecision = {
    trigger: 'issue_comment',
    labels: ['afk'],
    path: 'branch',
    // → remove needs-human-input, re-evaluate comments, then continue if the issue is now clear
  };

  const complexIssueDecision: WorkflowDecision = {
    trigger: 'issues.opened',
    labels: ['afk', 'complex-task'],
    path: 'complex-task',
    // → branch from main, create PRD/tasks only when needed, implement, review, and open a draft PR
  };

PRD Structure

Problem & Solution

User-facing problem statement and high-level answer for complex issues.

User Stories

Exhaustive numbered list: As an X, I want Y, so that Z.

Decisions & Testing

Modules, interfaces, schemas, and what/how to test — no file paths.

AFK vs Needs Human Input

AFK — Away From Keyboard

Issue is clear. Agent classifies, branches, and implements autonomously.

  • Title + description are specific and unambiguous
  • Scope is well-defined, no critical unknowns
  • Human can also force AFK by pre-adding the afk label

Needs Human Input

Issue is ambiguous. Agent posts all blocking questions as one comment and waits.

  • Requirements missing key details
  • Multiple valid interpretations with different outcomes
  • On reply: remove needs-human-input, re-evaluate, and re-add if still ambiguous

GitHub Agentic Workflow

The issue-automate workflow triggers on opened issues and only resumes on comments when needs-human-input is present. Clear issues become AFK, ambiguous issues pause for one grouped reply, and complex work flows through PRD/tasks only when required before a draft PR is opened.

1 · Clarify

  • Model judges title + description
  • Ambiguous → one comment with all questions
  • Human answers; model re-evaluates

2 · Branch & Build

  • Clear → label AFK and branch from main
  • Simple → implement directly
  • Complex → PRD first, tasks only if truly needed

3 · Draft PR

  • One draft PR per issue
  • Labeled automated and ready-for-review
  • PR link posted on the issue
